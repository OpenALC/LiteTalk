# 已批准的破坏性变更允许清单（oasdiff，见 .github/workflows/ci.yml「契约破坏性变更」）。
#
# 目的：让 CI 只对「新增且未批准」的破坏性变更失败。每条目精确匹配 oasdiff
# breaking 输出的四元组（check id + HTTP 方法 + 路径 + 描述），不支持通配/前缀，
# 因此不会吞掉后续改动：同一路径上描述不同的新破坏性变更仍然会失败。
#
# 格式：<check id>	<HTTP 方法>	<路径>	<oasdiff 描述>
# 四列必须用制表符分隔；# 开头为注释，空行忽略；重复条目会被 gate 拒绝。
#
# 新增条目必须先在 issue 中批准并在提交信息里引用单号；禁止批量粘贴未审阅条目。
#
# 当前全部条目依据 #31（REST 破坏性改造：ID 由 int64 字符串化、错误体改 RFC 9457
# detail、游标分页等）。基线是 api/oasdiff-baseline.yaml（#31 之前的最后契约状态）。
# 最近 release tag 一旦包含 api/openapi.yaml，CI 会改用 tag 作为基线；届时这些条目
# 会显示为「允许清单未再用到」，可按提示清理。
